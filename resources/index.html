Plain-English vocabulary

Common terms, explained.

Search for a term or filter by tool. The note under each definition explains what to remember while you work.

01

Repository

Git

The project files together with their change history.

REMEMBERThe home for the project: files plus history.
02

Working tree

Git

The version of files on your computer right now.

REMEMBERRun git status to see what differs from the last commit.
03

Stage

Git

Choose which edits will be included in the next commit.

REMEMBERStaging is a selection step, not an upload.
04

Commit

Git

A named snapshot in local repository history.

REMEMBERA commit does not automatically reach GitHub.
05

Branch

Git

A named line of work for a task or feature.

REMEMBERMake a feature branch so the change can be reviewed separately.
06

Remote

Git

Another copy of a repository, usually hosted on GitHub.

REMEMBERgit push sends commits to the configured remote.
07

Issue

GitHub

A place to describe a task, problem, or outcome before coding.

REMEMBERWrite acceptance criteria that someone else can verify.
08

Pull request

GitHub

A review page comparing your branch with its target branch.

REMEMBERRead Files changed and check the issue before merging.
09

Diff

Git / review

A line-by-line view of what was added, changed, or removed.

REMEMBERgit diff shows unstaged edits; git diff --staged shows staged edits.
10

Build

Delivery

The step that turns source files into output ready to publish.

REMEMBERThe build can fail even when the local editor looks fine.
11

Workflow

Delivery

A sequence of automated jobs and steps, often run by GitHub Actions.

REMEMBEROpen the run and find the failed step; do not guess.
12

Deploy

Delivery

Publish the built output so other people can open it.

REMEMBERWait for the deployment to finish, then open the published URL in a browser.
