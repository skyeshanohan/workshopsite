Agenda and teaching notes

Follow the slide deck in order. Pause on each black “Ask the room” bar. Leave a slide up until its checkpoint is true for most students.

0:00–0:25 · orient and unblock

Show a finished portfolio first. Use the starter-download slide until every student has an unzipped ZIP. Keep environment setup time-boxed: if a student is blocked after the setup segment, pair them with a working machine or checkpoint so learning can continue.

0:25–1:05 · repository and VS Code

Explain Git vs GitHub with the pipeline slide. Create an empty public repo (show the New repository screenshot), then find src/data/profile.js via the Explorer diagram. Avoid deep Git internals.

1:05–1:35 · personalize and preview

Have students open src/data/profile.js first: name, experience, projects, optional public/photo.jpg. Copilot is optional after that. Inspect the diff and remind them that public pages expose whatever they publish.

1:45–2:15 · requirement through pull request

Have each student create one issue with acceptance criteria. Their implementation should be small enough to review. Require them to explain the diff before merging.

2:15–2:45 · deploy and validate

Show where the Pages deployment workflow runs. Explain that a successful local preview doesn't prove the deployed path works. Check Actions logs and the actual published URL.

2:45–3:00 · recovery and close

Protect the final 15 minutes. Students who are behind use checkpoints; those finished polish accessibility or content. Capture live URLs and one takeaway.

Copilot prompt examples

Explain before editing

Explain the files, how this Astro project renders the page, and where content and styling are defined. Don't edit files yet. Give me a short map of the project.

Implement a focused requirement

Requirement: add a featured project card titled [PROJECT]. Acceptance criteria: title, short summary, relevant skills, and a working link; responsive on mobile; no new dependencies. Propose a plan before editing, then show me the changed files.

Review generated changes

Review the diff against these acceptance criteria: [CRITERIA]. Look for broken links, accessibility issues, responsive layout regressions, hard-coded secrets, and unnecessary complexity. Report findings before changing anything.

If someone falls behind

  1. Ask what already works; do not restart the entire setup.
  2. Catch-up path: fresh starter ZIP, workshop1-demo-portfolio ↗, or student-guide Step 6 for Pages.
  3. Have them create their own repository and personalize at least one item when time allows.
  4. Rejoin the shared exercise at the next milestone.
  5. Record what they skipped and share the walkthrough for self-paced review.

Troubleshooting quick guide

GitHub sign-in fails

Verify browser sign-in and VS Code authentication separately. Check that the student is using the intended GitHub account and has access to the repository.

Copilot isn't available

Check the account shown in VS Code, license activation, and the Copilot extension status. Have the student follow the exercise instructions without AI while the access issue is resolved.

The site works locally but not on Pages

Inspect the latest Actions run, check the configured Pages source, and confirm the site's base path matches the repository name.

A merge conflict appears

Have them pause and read the conflict markers. Explain the two competing versions before accepting either one; use the checkpoint branch if time is short.

Before students leave

  • Repository URL works and contains the student's project.
  • At least one issue / branch / pull request flow was completed or demonstrated with a checkpoint.
  • Live site URL is recorded, or the exact deployment blocker is known.
  • Student can state one Git concept and one Copilot change they reviewed.

Keep public portfolio content professional. Students should not publish private contact details, credentials, or information about other people without permission.
